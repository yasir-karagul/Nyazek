# Security review — ADR-0005: Decision authority delegated to Claude
Date: 2026-11-17 · Reviewer agent: `security-reviewer` (fresh context) · Scope: `docs/adr/0005-decision-authority-delegated-to-claude.md`; the matching `CLAUDE.md` rules (session protocol, "Delegated decisions", "Local only", "No invented rules", "Workflow authority", "Nothing unrecorded"); `docs/adr/0003-task-closure-by-claude.md` and `docs/adr/0001-development-workflow.md` for context; `docs/prd/05-trust/security.md` §9 (AGT-1 to AGT-6); `docs/prd/08-engineering/claude-workflow.md` §1–§4 and §7 (protected paths, GRD-1 to GRD-11); `docs/prd/00-governance/open-decisions.md` (header and register); `tasks/MASTER_TASKS.md` header. Working tree, uncommitted (the repository has no commits). · Follows up: —

The owner's choice to delegate is taken as given and is not a finding. The review judges how the delegation is bounded as a security control: whether one agent can now approve its own security-sensitive work or loosen the controls that bound it. PRD sections `05-trust` (T-0007) and `08-engineering` (T-0010) are `done`, so their rules are binding. The owner's delegation in chat does not change them. Only a recorded change to those rules does.

## Verdict
changes required

Summary: ADR-0005 leaves the owner's mandates and external actions with the owner. But (a) it removes the only human gate on protected paths (ledger, wallet, payments, identity, migrations, CI, infrastructure) without amending the PRD rules that require that gate, and (b) it lets Claude accept changes to the security rules, the reviewer definitions and the closure conditions that bound Claude. Together these let one agent write, review (through subagents it starts and scopes), close and re-scope its own money-moving and access-control work. Both are critical. The owner's own wording ("strictly adhering to the established workflow to ensure the platform remains protected") supports keeping the established protected-path gate, not removing it.
